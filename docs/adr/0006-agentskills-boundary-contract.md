# 0006 — Boundary contract between `homebrew-tap` and `agentskills`

**Scope.** Two repos, one contract. `jwa91/agentskills` owns all skill content (`skills/<name>/SKILL.md` + scripts/references/assets), the `agentskills` Go CLI source under `tools/agentskills/`, and both release tag streams (`<skill>/vX.Y.Z` for skills, `vX.Y.Z` for the binary). `jwa91/homebrew-tap` owns the distribution shell only: `Formula/agentskills.rb` (auto-written by the agentskills repo's `.goreleaser.yaml`, same mechanism `prehandover` uses) and the corresponding `tap.toml` row. Cross-references run in one direction at the file level — agentskills' goreleaser writes into homebrew-tap's `Formula/` — and in one direction at the install level — homebrew-tap's bootstrap invokes `agentskills bootstrap --skill jwa-tobrew --skill tap-alignment …` to materialise its tap-managing skills under `.agents/skills/` (generated, gitignored). Neither repo references the other by path inside source code, and skill content is **never** embedded in the Go binary: the CLI clones `github.com/jwa91/agentskills` at install time into `~/.cache/agentskills/repos/`. The CLI has no `uv`, `pip`, `npm`, or other language-runtime dependency on the user's machine; scripts that ship inside a skill's `scripts/` directory are the skill's runtime concern and are copied verbatim by the CLI without execution. **Why.** Single-purpose repos. The tap is a distribution channel; treating it as a skill registry too forced 4 skills to be vendored in-place and kept in sync by hand, which is exactly the drift that `tap-alignment` exists to detect. Splitting on the boundary above lets each repo release on its own cadence (skill edits never bump the CLI; CLI bumps never touch the tap), keeps `brew install jwa91/tap/agentskills` working on a clean macOS box with no Python or Node toolchain, and gives `align` a real source of truth — drift is no longer "do these 4 skill dirs in two repos still match?" but "does `agentskills bootstrap` succeed against the pinned ref?". The one-direction file write (agentskills → tap) mirrors the established `jwa-tobrew`-managed and source-repo-managed split (ADR-adjacent: see the briefing at `agentskills/docs/cli-go-port-briefing.md`), so the tap remains a single mechanical sink for every project it publishes.
