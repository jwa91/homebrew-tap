# 0003 — No hardcoded UUIDs, item names, or secret references in source

**Scope.** Source code in `cmd/jwa-tobrew/` contains zero references to specific 1Password items, vault names, or secret-store identifiers. The only knobs are `BREWTAP_DIR`, `BREWTAP_TAP_OWNER`, and `BREWTAP_TAP_NAME` — all infrastructure metadata, none of them secret references. The 1Password item that backs the tap-writer PAT is named only in `.env.template` (as an `op://` reference) and in a single Makefile constant for bootstrap. **Why.** Hardcoded "default" UUIDs in shipped binaries leak organizational structure to anyone running `strings`, make the binary unforkable for anyone with a different setup, and tempt future contributors into "just override it for prod." Forcing every reference through env (resolved by `op run` at runtime) means the tool is portable, every project owns its own scope, and a compromised binary surfaces nothing about which 1P items exist. If you find yourself wanting to add a "default" back, that's a sign you should be writing config docs, not source code.
