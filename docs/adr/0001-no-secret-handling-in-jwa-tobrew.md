# 0001 — jwa-tobrew does not fetch or manage secrets

**Scope.** The `jwa-tobrew` binary reads `$GITHUB_TOKEN` (or `$GH_TOKEN`) directly from its inherited environment when it needs to hit the GitHub API, and errors clearly with a pointer to `jwa-harden run` when the env is empty. It contains no 1Password integration, no keychain integration, no token validation, no token rotation, and no `TokenSource` resolver chain. It does not log secrets and does not log usage either. **Why.** Secret resolution is the responsibility of `jwa-harden` (planned, see `~/dotfiles/TODO.md`); every `jwa-*` CLI consumes whatever env it inherits, and `jwa-harden run -- <cmd>` is the canonical wrapping layer. Co-locating secret handling inside every tool would duplicate the rotation logic, fragment the audit trail (one usage log per tool vs. one per harden), and make least-privilege harder to reason about. Future agents reviewing this code should resist reintroducing any token-source abstraction here.
