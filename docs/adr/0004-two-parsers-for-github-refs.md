# 0004 — Two distinct parsers for GitHub references

**Scope.** `parseRepoRef` (in `cmd/jwa-tobrew/github.go`) is the canonical parser for *one string* representing a GitHub repo: CLI input, git origin URL, anything the user or git hands us. `findRepoRefInBody` (in `cmd/jwa-tobrew/manifest.go`) is the body-scanning regex that pulls the first `github.com/owner/repo` substring out of a `.rb` file. They are intentionally separate functions with different signatures and different error semantics. **Why.** They solve different problems: validating a single string the user typed (must be exactly one, must be github.com, errors should guide toward the right form) versus extracting the source repo from arbitrary text where multiple URLs might appear and the first match wins. Merging them would either weaken `parseRepoRef`'s validation (silently picking the first match in a malformed input) or over-constrain the body scanner (rejecting `.rb` files that mention non-GitHub URLs in comments). Two small focused functions are cheaper to maintain than one branchy one.
