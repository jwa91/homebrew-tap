# 0005 — No `.env` files; only `.env.template` with `op://` references

**Scope.** This ADR governs the tap-scoped enforcement of the universal `.env` / `op://` rule: (a) this repo's own `.env.template` (specific to `jwa-tobrew` publisher operations — `GITHUB_TOKEN`, etc.), which uses `op://` references and is the only `.env*` file committed here; (b) what `jwa-tobrew init` writes into every project it scaffolds — the `.env.template` shape, the `.gitignore` entries for `.env*`, and the `op run --env-file=.env.template -- <command>` invocation baked into `scripts/release.sh`. The universal machine-wide rule lives at `~/dotfiles/docs/adr/0001-no-env-files-op-templates.md` (and `~/dotfiles/docs/security-ground-rules.md` Rule 2); this ADR adds nothing to that policy — it records where the policy is *enforced for projects published through the tap*. **Why.** Per ADR 0007, the tap is the publish-channel boundary and `dotfiles` owns the machine-level security model; co-locating the universal rule here would duplicate it and inevitably drift, so the universal version lives upstream in dotfiles and this ADR exists only because the tap is the *enforcement mechanism* — every project scaffolded by `jwa-tobrew init` inherits the contract via the templates `init` writes, and the convention checker (`jwa-tobrew align`) is what makes the rule mechanically enforceable across all tap-published projects.
