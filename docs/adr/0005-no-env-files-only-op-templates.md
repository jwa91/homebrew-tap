# 0005 — No `.env` files; only `.env.template` with `op://` references

**Scope.** This repo (and every project scaffolded by `jwa-tobrew init`) commits an `.env.template` whose values are `op://` references and gitignores every real `.env` variant (`.env`, `.env.local`, `.env.*.local`). The `.gitignore` rules are added by `init` automatically. The canonical way to run anything that needs the resolved env is `op run --env-file=.env.template -- <command>` (or `jwa-harden run --` once that exists), which resolves the references in-process and never writes them to disk. **Why.** Per security ground rules Rules 2 and 5, 1Password is the single source of truth for long-lived secrets and `.env` files are forbidden anywhere — repos, `~/.config`, CI runners, containers. A real `.env` accidentally committed is the most common credential-leak vector in personal projects; banning the file shape entirely (rather than relying on careful gitignore per repo) makes the rule mechanically enforceable. The `op://` reference in `.env.template` is non-secret and useful documentation: it tells the next reader exactly which 1P item powers this project.
