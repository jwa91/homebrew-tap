# 0002 — Tap pushes use SSH, never an HTTPS-with-token flow

**Scope.** `jwa-tobrew` invokes plain `git push` against the tap's `origin` remote and refuses to operate when that remote is HTTPS, with an error directing the user to `git remote set-url origin git@github.com:OWNER/REPO.git`. There is no `WithTokenEnv`-style wrapping around `git push`, no credential helper integration, and no fallback to HTTPS+PAT pushing. **Why.** Per the security ground rules (`~/dotfiles/docs/security-ground-rules.md` Rule 1), SSH keys are the human's identity and tokens are for automation acting via the API. Wrapping `git push` with `$GH_TOKEN` works mechanically but crosses the actor boundary, makes it ambiguous which credential is in play, and creates a fallback path that defeats the principle of "tokens only for API calls." Failing loudly when origin is HTTPS surfaces the misconfiguration once rather than hiding it forever.
